# 审计追踪实施说明

## 已实现的边界

```text
Agent / BrokerClient 生成 trace_id
        ↓ Named Pipe
Broker 从 Pipe 读取 SID（不信任客户端传来的身份）
        ↓
审批状态变更 + audit_outbox 事件（同一 SQLite 事务）
        ↓
Broker 投递到 Windows Application / OpsAgent Broker
        ↓ 失败
SQLite 保留事件并在下一次 Broker 请求时重试
```

事件固定包含 `event_version`、`event_id`、`timestamp`、`component`、`event_name`、`severity`、`outcome`、`trace_id`、`request_id`、`actor_ref` 和受限 `fields`。`actor_ref` 是本机随机密钥计算的 HMAC 截断值，用于关联同一主体但不在普通 Event Log 中泄露 SID。

## 启用和查看

以管理员身份运行一次：

```powershell
.\scripts\install_event_log_source.ps1
```

然后重新启动 Broker。执行一次“清空会话记忆”并批准后，可查看：

```powershell
Get-WinEvent -LogName Application -ProviderName 'OpsAgent Broker' |
  Select-Object -First 20 -ExpandProperty Message
```

同一个 `trace_id` 应有 `approval.created`、`approval.approved`、`approval.executing` 和 `approval.executed`。若 Event Log 来源尚未注册或写入暂时失败，Broker 响应的 `audit_delivery.failed` 会大于零；事件仍保存在 `data/runtime/approvals.db` 的 `audit_outbox`，不会静默丢失。

## 已验证与尚未验证

`tests/test_audit.py` 覆盖：trace 连续性、SID/令牌预览脱敏，以及 Event Log 失败后 outbox 重试。证据会写入 `reports/latest_verification.json`。

当前没有把 Event Log 注册、日志 ACL、Broker Windows Service、独立服务身份或 ETW 伪装成已完成。这些都需要管理员权限和 Windows 实机集成测试。ETW 是后续用于高频、低开销性能事件的通道；本阶段 Event Log 是低频、持久的安全审计通道。
