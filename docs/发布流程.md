# 发布流程

## 发布前提

Release 只能在 CI 通过后创建。版本号位于根目录 `VERSION`，变更摘要位于 `CHANGELOG.md`，两者必须一致。

本地预检：

```powershell
.\.venv\Scripts\python.exe scripts\run_verification.py
.\.venv\Scripts\python.exe scripts\run_intent_eval.py
.\.venv\Scripts\python.exe scripts\run_rag_eval.py
.\.venv\Scripts\python.exe scripts\check_release.py --tag v0.4.0
```

## GitHub 发布

1. 推送到 `main`，等待 **Verify / Windows verification and evals** 成功。
2. 确认 `VERSION` 与 `CHANGELOG.md` 已更新并已合并。
3. GitHub 仓库进入 **Actions → Release → Run workflow**。
4. 输入和 `VERSION` 一致的版本，例如 `0.4.0`。
5. 工作流会再次运行测试和 Eval；只有全部成功时才创建 `v0.4.0` Release。

不要手工提前创建 tag 或 Release；不要把本机 `config/*.yaml`、`data/runtime/` 或密钥放入 Release 资产。

## 测试分组

```powershell
.\.venv\Scripts\python.exe scripts\run_test_group.py unit
.\.venv\Scripts\python.exe scripts\run_test_group.py integration
.\.venv\Scripts\python.exe scripts\run_test_group.py security
```

完整回归和 Eval 仍以 `run_verification.py`、`run_intent_eval.py`、`run_rag_eval.py` 为准。
